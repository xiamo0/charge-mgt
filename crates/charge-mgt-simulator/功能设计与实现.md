# charge-mgt-simulator 功能设计与实现文档

> **定位**: OCPP 1.6 交互式充电桩模拟器，一个窗口 = 一个充电桩

---

## 一、项目定位

**交互式仿真充电桩**——每个启动的 simulator 进程代表一个充电桩，通过 CLI 与用户直接交互：用户输入 JSON 报文，simulator 发送到 Gateway 并实时显示 Gateway 返回的响应或主动下发的命令。

### 核心价值

| 用途 | 说明 |
|---|---|
| **协议联调** | 开发者直接敲 JSON，观察 Gateway 的实时行为，无需写代码 |
| **问题定位** | 怀疑某个字段有问题时，手动构造并发送，快速验证 |
| **协议学习** | OCPP 初学者通过实际操作理解 Call/CallResult/CallError 模式 |
| **下行命令测试** | 通过 Cloud 侧推送命令，simulator 窗口实时看到并可回复 |
| **报文探索** | 自由实验各种 payload 组合，包括非法/边界情况 |

### 设计原则

- **一个进程 = 一个充电桩**：多桩测试时开多个终端窗口
- **JSON-in JSON-out**：协议层面保持原始信封 `[2/3/4, uid, ...]`
- **非阻塞 I/O**：读 stdin 与读 WebSocket 并行，互不阻塞
- **零代码即可用**：CLI 参数最小化，进入交互即可发报文

## 三、功能分层架构

```
┌──────────────────────────────────────────────────────────┐
│  main.rs                                                  │
│     CLI 解析 + WebSocket 连接 + REPL 启动                  │
├──────────────────────────────────────────────────────────┤
│  repl.rs  (核心 REPL 循环)                                │
│     - stdin 读取 (rustyline 增强：历史、行编辑)            │
│     - 命令解析 (help / quit / raw / respond / error / ...) │
│     - 输出格式化 (JSON 美化 + ANSI 颜色 + 时间戳)          │
├──────────────────────────────────────────────────────────┤
│  ocpp/client.rs (协议通信，非阻塞 I/O)                    │
│     - write task：用户输入 → WebSocket                     │
│     - read task：WebSocket → stdout (响应/主动命令)        │
│     - pending map：user Call ↔ CallResult 匹配             │
│     - server_calls map：server Call ↔ user respond 匹配    │
└──────────────────────────────────────────────────────────┘
```

### I/O 流水线

```
         ┌──────────────┐                    ┌──────────────┐
stdin → │ REPL reader  │ → parse → send ──▶│  WebSocket   │
         └──────────────┘                    │ (Gateway)    │
         ┌──────────────┐                    └──────────────┘
stdout ←│ REPL writer  │ ← format  ← recv ──┘
         └──────────────┘
```

- 两个独立 task：`reader_task` 阻塞读 stdin、`ws_read_task` 持续消费入站消息
- 互不阻塞：Gateway 推送命令时，用户的输入缓冲区不受影响

## 五、REPL 交互设计

### 5.1 输入格式

用户输入有三种语法，均支持：

| 语法 | 示例 | 含义 |
|---|---|---|
| **Shorthand** | `BootNotification {"vendor": "X"}` | 自动包 Call 信封 + 生成 uid |
| **Shorthand 带自定义 uid** | `/uid custom-1 BootNotification {}` | 同上但指定 uid |
| **Raw 信封** | `raw [2, "uid-1", "Heartbeat", {}]` | 按原样发送，不包装 |

**解析规则**：

```
输入开头 = '{' 或 '[' → 视为 raw JSON（需用户包完整信封）
输入开头 = 字母        → 视为 shorthand: <action> <optional-json>
输入开头 = '/'         → 视为命令（见 5.2）
```

### 5.2 命令清单

| 命令 | 别名 | 用途 |
|---|---|---|
| `help` | `?` | 显示帮助 |
| `quit` | `exit` | 关闭连接并退出；**Ctrl+D** 与 `quit` 等价 |
| `status` | `st` | 显示连接状态、pending 数、计数 |
| `raw <json>` | | 发送原样信封 |
| `/uid <id> <action> [payload]` | | shorthand + 自定义 uid |
| `respond <uid> <payload>` | `r` | 对 server call 回复 CallResult |
| `error <uid> <code> <desc>` | `e` | 对 server call 回复 CallError |
| `last` | `l` | 打印最近入站消息 |
| `last-sent` | `ls` | 打印最近出站消息 |
| `history` | `h` | 列出本次所有输入 |
| `replay <n>` | | 重发历史第 n 条（用新 uid） |
| `heartbeat-on <secs>` | `hb` | 启动后台心跳任务，每 `<secs>` 秒自动发 `Heartbeat {}` |
| `heartbeat-off` | `hbo` | 取消后台心跳任务 |
| `clear` | | 清屏 |

**Ctrl+D (EOF) 行为**（v2.1 新增）：

- rustyline 默认把 EOF 识别为 `ReadlineError::Eof`，当前设计显式把它映射为退出，与 `quit` 等价
- 与 `Ctrl+C (Interrupted)` 的语义区分：**Ctrl+D 直接退出，Ctrl+C 清当前行但不退出**（更贴近 bash/zsh 习惯）
- 退出前自动调用 `client.shutdown()`，发送 close frame

**命令拼写容错**（v2.1 新增）：

用户输入未知命令时，给出 "did you mean ...?" 提示，而不是无声跳过：

```
> statu
✗ Unknown command 'statu'

Did you mean?
  • status          show connection & pending state
  • st              status (shortcut)

Type 'help' to list all commands.
```

相似性算法：Levenshtein 距离 ≤ 2 且前缀至少匹配 3 字符时，列出候选（按编辑距离升序）。候选池包括命令名 + 所有别名。实现见 §7.3。

**心跳自动化**（v2.1 新增）：

某些 Gateway 要求充电桩定期心跳，否则主动断开。纯手工敲 `Heartbeat {}` 会累，提供后台开关：

```
> heartbeat-on 30
✓ Heartbeat task started (interval=30s, next send=14:30:50)
14:30:50 → [2, "u-auto-1", "Heartbeat", {}]
14:30:50 ← [3, "u-auto-1", {"currentTime": "2026-06-07T14:30:50Z"}]

> heartbeat-off
✓ Heartbeat task stopped (last sent=14:33:50, 6 total)
```

实现细节见 §7.6，由 `CancellationToken` 管理生命周期，确保 REPL 退出时干净停止。

### 5.4 输出格式规范

每条 I/O 均带时间戳 + 方向标识 + 颜色：

| 类型 | 前缀 | 颜色（`--no-color` 时失效） |
|---|---|---|

## 七、核心技术决策

### 7.1 OcppClient pending map 双轨设计

```rust
pub struct OcppClient {
    /// 出站 Call 等待响应：key = uniqueId, value = 打印回调
    pending_user_calls: Arc<Mutex<HashMap<String, PendingResponse>>>,
    
    /// 入站 Server Call 等待用户回复：key = uniqueId, value = action + 时间戳
    pending_server_calls: Arc<Mutex<HashMap<String, ServerCallInfo>>>,
    
    incoming_tx: mpsc::UnboundedSender<IncomingMessage>,  // 读 task → REPL
}
```

**关键设计**：

- `pending_user_calls`：用户发送 Call 后，记录 (uid, 打印回调/或只等匹配)
- `pending_server_calls`：服务端发起 Call 后记录，用户敲 `respond uid payload` 时取出并回包
- 两个 map 的 `uniqueId` 命名空间可以重叠（server call uid 由 server 决定，一般无冲突）

### 7.2 非阻塞 I/O 架构

```rust
async fn run() -> Result<()> {
    let client = OcppClient::connect(gateway_url, &config.id).await?;
    let mut readline = Editor::<()>::new();
    let (event_tx, mut event_rx) = mpsc::channel(100);
    
    // Read task：持续消费 WebSocket，把入站消息投递到事件流
    let reader_handle = tokio::spawn({
        let client = client.clone();
        let event_tx = event_tx.clone();
        async move { client.run_reader(event_tx).await }
    });
    
    // Main loop：交替等待 用户输入 和 入站事件
    loop {
        tokio::select! {
            // 非阻塞读 stdin（rustyline 阻塞 API 包装）
            line = spawn_blocking(move || readline.readline("> ")) => {
                match line {
                    Ok(text) => handle_repl_line(text, &client).await,
                    
                    // Ctrl+C：清当前行，继续 REPL（不退出）
                    Err(ReadlineError::Interrupted) => {
                        println!();  // 换行避免提示符被吞
                        continue;
                    }
                    
                    // Ctrl+D (EOF)：显式退出，与 quit 等价
                    Err(ReadlineError::Eof) => {
                        println!("\n🔌 EOF received, exiting...");
                        break;
                    }
                    
                    Err(e) => { eprintln!("readline error: {e}"); break; }
                }
            }
            // 入站事件（CallResult / CallError / Server Call）
            Some(event) = event_rx.recv() => {
                writer::print_incoming(event);
            }
        }
    }
    
    client.shutdown().await
}
```

**要点**：
- `tokio::select!` 让 stdin 读取与 WebSocket 事件接收互不阻塞
- 使用 `spawn_blocking` 包装 `rustyline` 的同步 API
- 入站事件通过 channel 投递，避免在 ws read task 内阻塞
- **v2.1 修订**：显式区分 `Interrupted` (Ctrl+C) 和 `Eof` (Ctrl+D) 两种终止信号
  - Ctrl+C 保留传统 Unix 语义：清输入 + 留在 REPL
  - Ctrl+D 显式退出 REPL，并在退出前调用 `client.shutdown()` 发送 close frame
- 两种分支都会先停掉后台心跳任务（通过 `CancellationToken`，见 §7.6）

### 7.3 REPL 解析器

`ReplCommand` 增加 `Unknown` 变体，用于触发"拼错提示"反馈。

```rust
pub enum ReplCommand {
    SendCall { action: String, payload: Value, uid: Option<String> },
    SendRaw { envelope: Value },
    Respond { uid: String, payload: Value },
    SendError { uid: String, code: String, description: String },
    Status,
    Help,
    Last,
    LastSent,
    History,
    Replay { index: usize },
    HeartbeatOn { interval_secs: u64 },
    HeartbeatOff,
    Clear,
    Quit,
    
    /// 未知命令：携带原始文本用于 "did you mean" 提示
    Unknown { input: String },
}

pub fn parse(line: &str) -> Option<ReplCommand> {
    // 1. 去掉前后空白 + 空行跳过
    // 2. slash 开头 → 命令模式
    // 3. raw/json 开头 → raw envelope
    // 4. 字母开头 → 首 token 当命令名去查表
    //    - 命中已知命令 → 返回对应 variant（解析剩余参数）
    //    - 未命中 → 走 fuzzy match，返回 Unknown(input) 让主循环打印提示
}

/// 候选池：命令名 + 所有别名
pub const COMMAND_TABLE: &[(&str, &str)] = &[
    ("help", "show help"),
    ("?",    "show help"),
    ("quit", "close connection and exit"),
    ("exit", "close connection and exit"),
    ("status", "show connection & pending state"),
    ("st",     "status (shortcut)"),
    // ...其他命令...
];

pub fn suggest_similar(input: &str) -> Vec<(&'static str, &'static str)> {
    // Levenshtein 距离 ≤ 2 且前缀至少匹配 3 字符
    // 返回: [(canonical, description), ...] 按距离升序
    COMMAND_TABLE.iter()
        .filter(|(name, _)| {
            levenshtein(input, name) <= 2
                && input.chars().zip(name.chars()).take(3).all(|(a,b)| a == b)
        })
        .copied()
        .collect()
}
```

**解析容错策略**：

1. 首 token 命中 `COMMAND_TABLE` 中的命令名或别名 → 正常分发
2. 首 token 为 `[` 或 `{` → 转 raw envelope
3. 首 token 为 `Heartbeat` / `BootNotification` / ... 等已知 OCPP action（来自 `ocpp_1_6::calls::*` 反射枚举或静态列表）→ 转 shorthand SendCall
4. 否则 → 返回 `Unknown { input }`，主循环打印格式化提示：

```rust
fn handle_unknown(input: &str) {
    let suggestions = suggest_similar(input);
    eprintln!("{} Unknown command '{}'", "✗".red(), input.bold());
    if !suggestions.is_empty() {
        eprintln!("\nDid you mean?");
        for (name, desc) in suggestions {
            eprintln!("  • {:<16} {}", name.yellow(), desc);
        }
    }
    eprintln!("\nType 'help' to list all commands.");
}
```

**设计取舍**：
- 不做 Tab 补全（rustyline 需要额外配置 `Completer` trait，留给 P2）
- `levenshtein` 直接用 `strsim` crate（已在常见 Rust 项目里），不自己实现

### 7.4 server call 的响应协议

用户可选三种方式回应：

1. **`respond <uid> <json>`** — 显式回复 CallResult
2. **`error <uid> <code> <desc>`** — 显式回复 CallError
3. **不回应（等待 / 忽略）** — 用于测试 Gateway 对未回应的超时行为

Server call 会一直保留在 `pending_server_calls` 直到用户回应或会话结束。

### 7.6 自动心跳任务（v2.1 新增）

**问题**：Gateway 通常要求充电桩按 `BootNotificationConf.interval` 周期发心跳。
纯 REPL 模式下用户必须每 N 秒手工敲 `Heartbeat {}`，调试 10+ 分钟很容易错过周期。

**方案**：通过 `CancellationToken` 管理的独立 tokio task，按需启停。

```rust
pub struct HeartbeatScheduler {
    cancel: CancellationToken,         // 控制 task 生命周期
    interval: Duration,
    sent_count: Arc<AtomicU64>,
    last_sent: Arc<Mutex<Option<Instant>>>,
    client: OcppClient,                // 复用共享 client
}

impl HeartbeatScheduler {
    pub fn start(client: OcppClient, interval_secs: u64) -> Self {
        let cancel = CancellationToken::new();
        let sent_count = Arc::new(AtomicU64::new(0));
        let last_sent = Arc::new(Mutex::new(None));
        
        tokio::spawn({
            let client = client.clone();
            let cancel = cancel.clone();
            let sent_count = sent_count.clone();
            let last_sent = last_sent.clone();
            async move {
                let mut interval = tokio::time::interval(Duration::from_secs(interval_secs));
                loop {
                    tokio::select! {
                        _ = cancel.cancelled() => {
                            info!("Heartbeat task stopped");
                            break;
                        }
                        _ = interval.tick() => {
                            if let Err(e) = client.call::<Value>("Heartbeat", json!({})).await {
                                warn!("Auto-heartbeat failed: {e}");
                            } else {
                                sent_count.fetch_add(1, Ordering::SeqCst);
                                *last_sent.lock().await = Some(Instant::now());
                            }
                        }
                    }
                }
            }
        });
        
        Self { cancel, interval: Duration::from_secs(interval_secs), sent_count, last_sent, client }
    }
    
    /// /heartbeat-off 触发的优雅停止
    pub fn stop(&self) {
        self.cancel.cancel();
    }
    
    pub fn stats(&self) -> (u64, Option<Instant>) {
        (self.sent_count.load(Ordering::SeqCst), *self.last_sent.lock().now_or_never())
    }
}
```

**与 REPL 集成**：

```rust
// main.rs
let mut heartbeat: Option<HeartbeatScheduler> = None;

// 命令分发
match cmd {
    ReplCommand::HeartbeatOn { interval_secs } => {
        if let Some(existing) = heartbeat.take() {
            existing.stop();  // 替换旧的
        }
        let scheduler = HeartbeatScheduler::start(client.clone(), interval_secs);
        let next = Local::now() + Duration::from_secs(interval_secs);
        println!("{} Heartbeat task started (interval={}s, next send={})", 
            "✓".green(), interval_secs, next.format("%H:%M:%S"));
        heartbeat = Some(scheduler);
    }
    ReplCommand::HeartbeatOff => {
        if let Some(scheduler) = heartbeat.take() {
            scheduler.stop();
            let (count, last) = scheduler.stats();
            println!("{} Heartbeat task stopped (last sent={}, {} total)",
                "✓".green(), 
                last.map(|t| format!("{:?}", t.elapsed())).unwrap_or_else(|| "never".into()),
                count);
        } else {
            println!("No heartbeat task running");
        }
    }
    // ...其他命令...
}

// REPL 退出前清理
if let Some(scheduler) = heartbeat.take() {
    scheduler.stop();
}
```

**关键设计点**：

1. **替换语义**：已运行时再次 `heartbeat-on 60` 会先 stop 旧 task，再启新的，避免多个 task 同时发心跳
2. **状态可见**：`status` 命令应打印心跳任务状态：
   ```
   heartbeat_task: running (interval=30s, sent=4, last=3s ago)
   ```
3. **退出清理**：在 `Eof` / `Interrupted` / `Quit` 分支的 shutdown 前，必须先 `scheduler.stop()` 再 `client.shutdown()`，否则 task 可能在 client 关闭后还在尝试 send
4. **与 `respond` / server call 不冲突**：HeartbeatCall 生成的 uid 与 server call 的 uid 命名空间隔离（见 §7.1）
5. **不自动响应 Cloud 心跳要求**：`interval` 必须由用户显式设置，避免 REPL 启动后自动刷屏

## 八、OCPP 2.x 可演进架构设计

为后续支持 OCPP 2.0.1/2.1，需要在 Phase 0（v1.6）时预留扩展点。

### 8.1 OCPP 版本差异概览

| 维度 | OCPP 1.6 | OCPP 2.0.1 / 2.1 |
|---|---|---|
| **信封格式** | `[2, uid, action, payload]` | 相同（仍是 JSON 数组） |
| **核心动作** | `Start/StopTransaction` | **`TransactionEvent`**（替代双事务） |
| **授权** | `Authorize` | `Authorize` + **ISO15118** 证书验证 |
| **安全** | 无 | **Security Profiles**（TLS、签名、证书管理） |
| **设备模型** | 无 | **Variables / Monitor** 完整设备模型 |
| **计费** | 无 | **Tariff & Cost / VariableUsage**（2.1 新增） |
| **消息名** | PascalCase | snake_case + 命名空间前缀 |

**核心结论**：信封解析可复用，业务消息不可复用。

### 8.2 核心抽象层（版本无关）

    StartTransaction { transaction_id: i32 },
    TransactionEvent { event_type: String, transaction_id: i32 }, // 2.0.1+

    StatusNotification,

}

| 组件 | 复用策略 |
|---|---|
| **WebSocket 连接管理** | `tokio-tungstenite` 封装 → `transport.rs` 统一层 |

### 8.6 关键差异点的处理

| 差异点 | 1.6 实现 | 2.0.1+ 实现 | 统一接口设计 |
|---|---|---|---|
| **事务模型** | Start/StopTransaction | TransactionEvent (Started/Updated/Ended) | `protocol.start_transaction()` / `end_transaction()` 返回统一 `transaction_id` |
| **授权** | `Authorize(idTag)` | `Authorize(idToken: {type, idToken})` | `protocol.authorize(id_token: IdToken)` |
| **计量上报** | `MeterValues(connectorId, transactionId?)` | `MeterValues(evseId, transactionId?, meterValue[])` | `protocol.send_meter_values(evse_id, tx_id?, values)` |
| **状态通知** | `StatusNotification(connectorId, status)` | `StatusNotification(evseId, connectorId, status)` | `protocol.notify_status(evse_id, connector_id, status)` |
| **证书/安全** | 无 | InstallCertificate, SignCertificate, DeleteCertificate | `protocol.security()` 返回 `Option<SecurityHandler>`，1.6 返回 None |
